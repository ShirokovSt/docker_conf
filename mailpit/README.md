# Mailpit — тестовая почта

Тестовый почтовый сервер: приложение отправляет письма на SMTP Mailpit, а они **никуда не уходят** и сразу появляются в веб-интерфейсе. Удобно проверять уведомления, рассылки, письма с вложениями и HTML-вёрстку, не рискуя отправить что-то реальным адресатам.

| | |
|---|---|
| Веб-интерфейс | http://localhost:8025 — без логина |
| SMTP для приложений на этом ПК | `localhost:1025` |
| SMTP для других контейнеров compose | `mailpit:1025` |
| TLS / SSL | не нужен (выключить в настройках приложения) |
| Логин и пароль SMTP | принимаются **любые** (или без них) |
| Контейнер / сервис | `mailpit` |
| Версия | Mailpit 1.31.5 |
| Данные | `mailpit\data\mailpit.db` — письма сохраняются между перезапусками |
| Сколько хранится | не больше **1000** писем и не старше **7 дней** — старые удаляются сами |

Запуск: `start.bat`, остановка: `stop.bat`, логи: `logs.bat`. Всё сразу — `start-all.bat` или `start-services.bat` в корне.

**Поменять лимиты хранения** — в интерфейсе их нет, только в `docker-compose.yml` у сервиса `mailpit`: `MP_MAX_MESSAGES` (количество писем, `0` — без ограничения) и `MP_MAX_AGE` (срок: `36h` или `14d`). После правки — `start.bat`: он пересоздаст контейнер с новыми значениями (пункт меню «Перезапустить» старые настройки не меняет). Письма при этом сохраняются; если новый лимит меньше, лишние старые удалятся.

## Подключение приложения

Spring Boot (`spring-boot-starter-mail`):

```properties
spring.mail.host=localhost
spring.mail.port=1025
# логин и пароль можно не указывать или оставить любые
spring.mail.properties.mail.smtp.auth=false
spring.mail.properties.mail.smtp.starttls.enable=false
```

Любой другой клиент: хост `localhost`, порт `1025`, без SSL/TLS и без STARTTLS. Если в приложении уже прописаны логин и пароль от боевого SMTP, их можно не убирать — Mailpit примет любые.

## Веб-интерфейс

http://localhost:8025:

| Что | Где |
|---|---|
| Список писем, поиск по отправителю, получателю, теме, тексту | главная страница, строка поиска |
| HTML-версия, текстовая версия, заголовки, исходник письма | открыть письмо → вкладки HTML / Text / Headers / Raw |
| Вложения — просмотр и скачивание | открыть письмо → список вложений |
| Проверка HTML: что не поддерживают почтовые клиенты (Outlook, Gmail и т.д.) | открыть письмо → вкладка HTML Check |
| Проверка ссылок в письме (битые ссылки) | открыть письмо → вкладка Link Check |
| Удалить одно письмо / все письма | кнопка Delete / Delete all |
| Отметить прочитанным, фильтр непрочитанных | меню слева |

Новые письма появляются сразу, без обновления страницы.

## Проверка и команды

Отправить тестовое письмо из PowerShell:

```powershell
Send-MailMessage -SmtpServer localhost -Port 1025 -From app@test.local -To user@test.local -Subject "Проверка" -Body "Привет из Mailpit" -Encoding UTF8
```

API — удобно в автотестах, чтобы проверить, что письмо ушло:

| Команда | Что делает |
|---|---|
| `curl http://localhost:8025/api/v1/messages` | список писем (JSON) |
| `curl "http://localhost:8025/api/v1/search?query=subject:Проверка"` | поиск писем |
| `curl http://localhost:8025/api/v1/message/latest` | последнее письмо целиком |
| `curl -X DELETE http://localhost:8025/api/v1/messages` | удалить все письма |

Полное описание API — в веб-интерфейсе: меню слева → **API**.

## Запасной вариант: docker run

Выполнять в cmd из папки `docker_conf` (`%cd%` — текущая папка).

```bat
docker run -d ^
  --name mailpit ^
  -p 1025:1025 -p 8025:8025 ^
  -v "%cd%\mailpit\data:/data" ^
  -e MP_DATABASE=/data/mailpit.db ^
  -e MP_MAX_MESSAGES=1000 ^
  -e MP_MAX_AGE=7d ^
  -e MP_SMTP_AUTH_ACCEPT_ANY=1 ^
  -e MP_SMTP_AUTH_ALLOW_INSECURE=1 ^
  axllent/mailpit:v1.31.5
```
