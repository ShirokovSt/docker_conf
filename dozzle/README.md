# Dozzle — логи всех контейнеров

Веб-интерфейс для логов Docker: логи **всех** контейнеров в одном окне в реальном времени, с поиском и несколькими контейнерами рядом. Удобнее, чем `logs.bat` в консоли. Сам ничего не хранит: читает логи напрямую у Docker.

| | |
|---|---|
| Веб-интерфейс | http://localhost:8098 — без логина, **только с этого ПК** |
| Контейнер / сервис | `dozzle` |
| Версия | Dozzle 11.3.5 |
| Какие контейнеры видны | все в Docker Desktop: этого проекта, TeamCity, запущенные через `docker run` |
| Данные | `dozzle\data` — только `dozzle.yml`, если менять настройки в интерфейсе |
| Память | ~30 МБ |

Запуск: `start.bat`, остановка: `stop.bat`, логи самого Dozzle: `logs.bat`. Всё сразу — `start-all.bat` или `start-services.bat` в корне.

## Что умеет

| Что | Где |
|---|---|
| Логи контейнера в реальном времени | выбрать контейнер в списке слева |
| Несколько контейнеров рядом | у контейнера в списке — значок «закрепить» (pin) |
| Поиск по логу (поддерживает regex) | строка поиска на странице контейнера (`Ctrl+F`) |
| Только ошибки / предупреждения | фильтр по уровню над логом |
| Скачать лог в файл | меню контейнера (⋮) |
| Нагрузка: CPU и память контейнера | график над логом, общая сводка — на главной |
| Запустить / остановить / перезапустить контейнер | меню контейнера (⋮) |
| Логи всех контейнеров группы (compose-проект) | список слева, группировка по проекту `devstack` |

> В меню контейнера есть ещё **«Удалить»** и **«Обновить»**. «Удалить» удаляет сам контейнер; данные в папках `<сервис>\data` и в именованных томах остаются, а контейнер пересоздастся при следующем `start.bat`. «Обновить» скачивает новый образ по тому же тегу — для закреплённых версий ничего не меняет.

Консоль внутри контейнера (shell) выключена — для неё `docker exec -it <контейнер> sh` или `cassandra\cqlsh.bat`.

## Почему только с этого ПК

Dozzle получает доступ к Docker целиком (через `docker.sock`), а с включёнными кнопками может останавливать контейнеры. Поэтому порт открыт только на `127.0.0.1`: с других компьютеров сети интерфейс недоступен.

## Настройки

Заданы в `docker-compose.yml` у сервиса `dozzle`, мастер первого запуска выключен:

| Переменная | Значение | Что делает |
|---|---|---|
| `DOZZLE_ENABLE_ACTIONS` | `true` | кнопки запуска, остановки, перезапуска |
| `DOZZLE_HOSTNAME` | `devstack` | имя в заголовке |
| `DOZZLE_NO_ANALYTICS` | `true` | не отправлять анонимную статистику |
| `DOZZLE_DISABLE_SETUP_WIZARD` | `true` | не показывать мастер настройки при первом запуске |
| `DOZZLE_RELEASE_CHECK_MODE` / `DOZZLE_IMAGE_CHECK_MODE` | `manual` / `off` | не проверять обновления в интернете |

После правки — `start.bat`: он пересоздаст контейнер с новыми значениями.

## Запасной вариант: docker run

Выполнять в cmd из папки `docker_conf` (`%cd%` — текущая папка).

```bat
docker run -d ^
  --name dozzle ^
  -p 127.0.0.1:8098:8080 ^
  -v /var/run/docker.sock:/var/run/docker.sock ^
  -v "%cd%\dozzle\data:/data" ^
  -e DOZZLE_HOSTNAME=devstack ^
  -e DOZZLE_ENABLE_ACTIONS=true ^
  -e DOZZLE_NO_ANALYTICS=true ^
  -e DOZZLE_DISABLE_SETUP_WIZARD=true ^
  -e DOZZLE_RELEASE_CHECK_MODE=manual ^
  -e DOZZLE_IMAGE_CHECK_MODE=off ^
  amir20/dozzle:v11.3.5
```
